为什么是 OC Desktop

为什么是 OC Desktop

完整的 opencode 体验，收进一个真正的桌面应用。

上游 opencode，零改动

官方 Web UI 与 agent 核心原样运行，工程侧只做幂等补丁；opencode 一发版即可跟进新能力。

进程内托管，同源加载

服务端在应用内部启动，界面经本机端口同源加载。一切留在本机 —— 无 CORS、无云端中转、无账号。

为鸿蒙补齐的能力

终端 PTY 与外部进程在鸿蒙不可得，因此改用纯 JS 工具覆盖 shell / grep / glob，功能落到应用自己的能力上。

克制的权限与品牌化

只申请必要的网络与文档目录权限；窗口标题、界面与图标统一为 OC Desktop，不暴露上游品牌。

OC Desktop · HarmonyOS Edition

进程内 Node + ArkWeb · 2in1 / 平板 · 第三方移植
  • 上游基线 opencode v2.0.26（分支 v2）

OC Desktop 是基于上游开源项目 opencode 构建的桌面端：Windows / Linux / macOS 版由上游官方分发；鸿蒙端有两个独立的第三方版别 —— HarmonyOS Edition（进程内 Node + ArkWeb，不带 Electron）与 Electron on HarmonyOS Edition（Electron 运行时）。均与上游团队无隶属关系。

鸿蒙端已知边界（两个版别相同）：终端 PTY、依赖外部进程的工具（LSP / MCP / git）在本平台不可用；插件在线安装默认关闭。HarmonyOS Edition 另外不随包分发 Chromium。

实现原理

一个服务端，一个源，零摩擦

  1. 1

    启动服务端

    应用在设备内启动 opencode 服务端（随机端口 + 访问密码）。

  2. 2

    同源加载界面

    渲染层（ArkWeb / Chromium）加载服务端内嵌的官方 Web UI。

  3. 3

    壳层接管

    凭据与请求头、数据目录、工具覆盖由壳层处理，界面无需改一行。
